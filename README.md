# plugin-morpherepo-go-psql

Generates Go PostgreSQL repository implementations from MorpheRepo data access contracts (`.repo` YAML) and Morphe model definitions (`.mod` YAML).

## Overview

This plugin takes **two inputs**:

1. **MorpheRepo specifications** (`.repo` files) — define *what* operations to generate (identifiers, filters, CRUD operations)
2. **Morphe registry** (`.mod` files via config) — define *how* to generate (field types, relations, FK columns)

It produces concrete `pgxpool`-backed Go structs that implement the repository interfaces generated by `plugin-morpherepo-go`.

## Input/Output

| | Format | Description |
|---|---|---|
| **Input** | `KA:MR1:YAML1` | MorpheRepo YAML contract files (`.repo`) |
| **Config** | Morphe registry path | Path to Morphe registry containing `.mod` model files |
| **Output** | `KA:MR1:GO_PSQL1` | Go PostgreSQL repository implementation files |

## Configuration

```yaml
# kalo.yaml
config:
  "@kalo-build/plugin-morpherepo-go-psql":
    models:
      PackagePath: "github.com/your-org/your-app/internal/types/models"
    repo:
      PackagePath: "github.com/your-org/your-app/internal/database/repo"
    morpheRegistryPath: "./morphe/registry"
```

## Generated Code

For each `.repo` specification, the plugin generates a Go file containing:

- **Struct**: `*Repository` with `*pgxpool.Pool`
- **Constructor**: `New*Repository(pool *pgxpool.Pool)`
- **GetAll**: With dynamic WHERE clause for optional filters (`*string` parameters)
- **GetByID / GetBy{Identifier}**: Per-identifier lookup methods
- **Create**: `INSERT...RETURNING` with all fields
- **Update**: `UPDATE...SET...RETURNING`, excludes `ID` and `CreatedAt`
- **Delete**: `DELETE...WHERE id = $1`

### Design Decisions

- **No JOINs**: Generated CRUD queries only SELECT the model's own columns (including FK columns). Relationship hydration via JOINs can be added via custom methods.
- **FK scanning**: `ForOne` FK fields are scanned as `*string` (nullable). `ForOnePoly` fields (`OwnerID`, `OwnerType`) are scanned as `string` (always present together).
- **Column ordering**: Alphabetical by field name, with direct fields first, then FK fields from relations.
- **Parameterized queries**: All queries use `$1`, `$2`, etc. for safe parameterized execution.
